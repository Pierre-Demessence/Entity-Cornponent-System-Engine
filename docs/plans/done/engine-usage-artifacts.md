# Plan: usage report artifacts (model → JSON + markdown + HTML)

## Problem

`scripts/engine-usage.ts` analyses the compiler program and renders markdown in
one pass. The analysis is the expensive, interesting part; the rendering is
string assembly. That coupling means there is exactly one consumer of the data
(the committed markdown), so anything interactive — sorting 42 modules by
"how much of this module is unproven", filtering to the gaps — needs a new
generator rather than a new view.

## Decision (with user)

Split the generator into a **plain-data model** plus three renderers:

```
compiler program ─▶ buildUsageReport()   → UsageReport (JSON-able, sorted)
                          ├─▶ markdown  docs/agent/engine-usage.md    (committed, drift-guarded, AI-readable)
                          ├─▶ JSON      docs/agent/engine-usage.json  (committed, drift-guarded, the data contract)
                          └─▶ HTML      docs/agent/engine-usage.html  (generated, gitignored, local lens)
```

- **Markdown stays first-class.** It is what an agent reads, and it stays
  drift-guarded by `npm test`.
- **JSON is committed** and drift-guarded too. It is the artifact other tools
  (and, later, a possible `examples/hub` coverage panel) can consume.
- **HTML is not committed.** GitHub renders `.html` as source rather than a
  preview, so committing it buys nothing but diff noise; `.gitignore` already
  handles the same pattern for `examples/*/dist`. It is regenerated by
  `npm run docs:usage`, and it must be **self-contained** — the data is inlined
  rather than `fetch`ed, because `file://` blocks cross-origin fetches.
- **No CSV.** The module → symbol → consumers nesting flattens badly into
  columns, and any CSV is a five-line transform away from the JSON.

## Design

### Model (all JSON-able: arrays, never `Set`/`Map`; every list sorted)

```ts
export interface BucketUsage {
  consumers: string[];
  /** Value symbol whose references in this bucket are all type-position. */
  typeOnly: boolean;
}
export interface SymbolUsage {
  name: string;
  kind: SymbolKind;
  isValue: boolean;
  example: BucketUsage;
  test: BucketUsage;
  other: BucketUsage;
  coveredByExample: boolean;    // value: a value-position example reference
  noExternalConsumer: boolean;  // nothing outside the symbol's own source
}
export interface EntryUsage {
  importPath: string;
  isModule: boolean;
  symbols: SymbolUsage[];
  valueUsedByExample: number; valueTotal: number;
  typeUsedByExample: number;  typeTotal: number;
  examples: string[]; tests: string[]; other: string[];  // unions across symbols
  coveredByExample: boolean;
}
export interface ExampleUsage { name: string; entries: number; value: number; type: number }
export interface CandidateUsage { importPath: string; missing: number; total: number }
export interface UsageReport {
  headline: {
    entries: number; coreEntries: number; modules: number;
    symbols: number; valueSymbols: number; typeSymbols: number;
    entriesWithExample: number; entriesWithoutExample: number;
    valueWithoutExample: number; valueWithNoConsumer: number; noExternalConsumer: number;
  };
  entries: EntryUsage[];       // sorted by importPath
  examples: ExampleUsage[];    // sorted by reach desc, then name
  candidates: CandidateUsage[]; // sorted by missing desc, then importPath
}
```

Determinism is a contract: no timestamps, no absolute paths, no unsorted
collections, so both committed artifacts are byte-stable across machines. JSON
key order follows the object literals in the model builders, so `npm run
lint:fix` — which alphabetizes those keys — changes the JSON and needs a
regenerate. That surfaces as a drift-test failure, never as silent corruption.

### Renderers

- `buildUsageReport()` — program + collection + self-check, returns the model.
- `renderUsageMarkdown(report)` — must reproduce today's markdown **byte for
  byte**; a diff of the regenerated file proves the refactor was faithful.
- `renderUsageJson(report)` — `JSON.stringify(report, null, 2)` + trailing LF.
- `renderUsageHtml(report)` — one self-contained file: headline numbers, a text
  filter, "gaps only" / "modules only" toggles, a sortable entries table
  (click a column header), and a row expansion showing that entry's per-symbol
  consumers. Vanilla JS and inline CSS, no dependency, no network. The inlined
  JSON escapes `<` so a `</script>` sequence can never break out.

`generateEngineUsageMarkdown()` is deleted rather than kept as a wrapper: the
CLI and the drift test are the only call sites, and pre-1.0 tooling needs no
compatibility shim.

### Plumbing

- `engine-usage.gen.ts` writes all three files and logs their paths.
- `.gitignore` gains `docs/agent/engine-usage.html`.
- `engine-usage.test.ts` builds the report **once** (`beforeAll`) and reuses it:
  - markdown drift, JSON drift;
  - invariant: `renderUsageMarkdown(JSON.parse(json))` equals the committed
    markdown, so the two artifacts cannot drift apart;
  - structural: the model covers every `readEntries()` entry;
  - existing exclusion/classifier unit tests stay as they are.

## Non-goals

- Committing the HTML, or adding any HTML build step/dependency.
- CSV, or a coverage threshold that gates CI.
- Changing the report's semantics (references not exercise, exclusions, buckets).

## Peer review → LGTM

One read-only pass (small model, no edits, no `vscode_askQuestions`) over the
model/renderer split: nothing actionable on model completeness, determinism, test
quality, HTML safety, scope or docs. It confirmed that the markdown's
byte-identity with the pre-refactor commit is valid fidelity evidence, and that
the inlined HTML re-derives the same semantics (the `(type only)` suffix, the
"no external consumer" marking) instead of inventing its own.

Verified here: `npm run lint` and `npm run typecheck` clean; `npm test` 83 files /
1425 tests; the HTML lens driven in a browser — 58 entry rows, sort by header
(both directions), row expansion, text filter, both toggles, 28 example rows.
