# Co-locate core-primitive guides with their source

Give the eight core-primitive deep-dives the same treatment modules already get:
the guide lives next to the code it documents and is published to the website
Manual. This makes `/docs` unambiguously internal.

## Problem

The engine follows a co-location rule for modules — the guide is
`src/modules/<name>/README.md`, auto-published to the Manual — but breaks it for
core primitives:

- Core guides live in `docs/*.md`, mixed in with internal governance
  (`extending-the-engine.md`, `plans/`, `roadmap/`, `archived/`, `agent/`).
- They are **not** published to the Manual; a core primitive gets only an API
  reference page, never a guide page.

So `/docs` mixes consumer deep-dives with internal governance, and core
primitives are second-class next to modules.

## Approach (Option A)

1. Move the eight core guides from `docs/` to sit beside their source in `src/`:
   `component-store`, `event-bus`, `query`, `scheduler`, `spatial-structure`,
   `template`, `tick`, `world` → `src/<name>.md`.
2. Extend the Manual generator (`scripts/manual.ts`) to publish them as a **Core**
   group, alongside the existing **Modules** group.
3. `/docs` becomes purely internal governance.

### Manual layout change

- Module pages move `manual/<name>.md` → `manual/modules/<name>.md`.
- Core pages publish to `manual/core/<name>.md`.
- Sidebar gains explicit **Core** and **Modules** groups (autogenerated per
  subdirectory), ordered Core-first.

### Link rewriting

`resolveLink` becomes resolution-based: resolve every in-repo link to a repo
path, then classify — core guide (`src/<name>.md`) → core route, module guide
(`src/modules/<name>/README.md`) → module route, `docs/` → dropped (internal),
else GitHub source / examples. Cross-group routes are `../../<group>/<name>/`.
